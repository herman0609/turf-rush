# 功能说明

本文逐项列出游戏的全部功能，每项都写明怎么触发，以及看到什么才算正常。运行方法见 [README](../README.md)；设计取舍和原因见 [DECISIONS](DECISIONS.md)。

## 1. 进入游戏与房间

| 功能 | 怎么用 | 细节与预期 |
|---|---|---|
| 昵称 | 首页自动生成一个随机昵称（形容词 + 动物，比如"迅捷的柴犬"），可以直接修改，也可以点「换一个」 | 昵称保存在浏览器本地，下次打开时自动填上。规则：1–12 个字符，去掉首尾空格、控制字符和换行；同一房间里有人重名时，自动加数字后缀（例如"阿橙2"） |
| 创建房间 | 首页点击「创建房间」 | 进入大厅，显示 5 位房间码和邀请链接 `/r/房间码`，创建者成为房主 |
| 房间码 | 5 位，只用 `23456789ABCDEFGHJKMNPQRSTUVWXYZ` 这些字符 | 不使用容易看错的 0 / O、1 / I / L。输入时不区分大小写，空格和横线会被忽略，比如输入 `ab 2-cd` 等同于 `AB2CD` |
| 邀请 | 大厅里点击「复制邀请链接」；在支持系统分享的设备上（手机浏览器、macOS Safari 等）还会出现「分享」按钮 | 复制后页面提示"邀请链接已复制，发给朋友吧"；如果浏览器不允许访问剪贴板，会提示手动复制，链接就显示在输入框里。「分享」会调起系统分享面板，内容是"来和我抢地盘！房间码 XXXXX"加上邀请链接。邀请链接使用当前地址栏里的域名，所以局域网联机时，要先用本机 IP 打开页面再复制 |
| 通过链接加入 | 打开邀请链接，确认昵称后点击「加入」 | 不需要账号，也不需要再输入房间码 |
| 通过房间码加入 | 首页输入房间码，点击「加入」 | 和打开链接的效果一样 |
| 无效房间码 | 打开一个不存在的房间，比如 `/r/ZZZZZ` | 显示"房间不存在或已失效"，并说明可能的原因（输错了、长时间无人被清理、服务重启），提供「创建新房间」和「返回首页」 |
| 大厅 | 创建或加入房间之后 | 显示玩家列表（颜色、形状、昵称，以及"房主""你""已准备"等标记，掉线的人会显示"掉线，重连中 Ns"）、观战人数和静音按钮 |
| 准备与开始 | 非房主点击「准备」；房主点击「开始游戏」 | 房主不需要准备。按钮下方的提示会说明还差什么："至少需要 2 名玩家"、"等待 xx 准备"、"等待 xx 重连"；条件都满足后显示"人齐了，开始吧！"。只有房主能开始 |
| 离开房间 | 大厅或结算页点击「离开房间」 | 立即被移出房间，并回到首页 |

## 2. 规则与操作

**地图与目标**：地图是 32×20 的网格，2–4 名玩家从四个角出发。角色会一直前进，走过的格子染成自己的颜色，也可以覆盖别人的颜色。分数就是当前拥有的格子数，60 秒结束时分数最高的人获胜，分数相同则并列。

**移动规则**：
- 常速约每秒 6.7 格（每 3 个 tick 前进 1 格）。
- 转向会在进入下一格时生效。连续快速按两个方向，可以提前排好两次转弯，最多排 2 次。
- 允许直接掉头。
- 撞墙后停住，按一个新方向就继续走。
- 玩家之间没有碰撞，可以互相穿过。

**冲刺**：0.6 秒内速度变为三倍（每个 tick 1 格），冷却 4 秒，冷却从冲刺开始时计算。HUD 底部会显示"冲刺就绪 [空格]"或"冲刺冷却 2.3s"，自己角色身上的环形进度也表示冷却。

| 操作 | 键盘 | 手机触屏 |
|---|---|---|
| 转向 | 方向键或 WASD | 在棋盘上滑动，超过 22 px 算一次转向；不抬手可以连续转几次弯 |
| 冲刺 | 空格 | 轻点棋盘（250 ms 内且没有滑动），或者点右下角的「冲刺」按钮（只在触屏设备上显示） |
| 静音 / 取消静音 | M | 点右上角的喇叭图标 |
| 调试面板 | `` ` ``（反引号键） | 在地址后加 `?debug=1` |

**区分玩家**：每名玩家都有四重标识：颜色、形状、地块纹理、头顶昵称。颜色取自 Okabe-Ito 色盲友好色板（蓝、橙、绿、紫），形状分别是圆、三角、方、菱形，纹理分别是圆点、斜纹、网格和横纹。所以即使分不清颜色，也能认出谁是谁。自己的昵称后面带"（你）"，开局时角色外面有脉冲光圈。

## 3. 游戏反馈（画面、动画与声音）

| 时机 | 画面 | 声音 |
|---|---|---|
| 开局 | 3-2-1 倒计时数字放大淡出，自己的角色外有脉冲光圈 | 倒数提示音，出发时一声"Go" |
| 染色 | 格子弹出，伴随粒子；连续染色时音调逐步升高 | 染色音（带连击）；抢到别人的格子和自己的格子被抢，各有不同的提示音 |
| 冲刺 | 角色后面拖出残影，冷却环转动 | 冲刺音；冷却结束时有"就绪"提示音 |
| 比分 | 顶部是每名玩家的分数卡，领先者带皇冠；下方的比分条按占比实时伸缩 | 自己领先或被反超时有提示音 |
| 反超 | 弹出提示："你反超了！"、"被 xx 反超了！"、"xx 反超！" | 同上 |
| 最后 10 秒 | 计时器变红，棋盘边框变成橙红色 | 每秒一声心跳，越接近结束越急 |
| 时间到 | 全屏显示"时间到！"，随后出现结算卡 | 结束音 |
| 结算 | 名次、格数和占全图的百分比，同分同名次；标题会写"你赢了！"、"平局！"、"平局！你并列第一"或"xx 获胜！"；副标题写明领先多少格，提前结束时写明原因；赢家这一侧有彩带 | 胜利、失败、平局各有不同的音效 |

**声音**：全部用 WebAudio 现场合成，没有任何音频文件。浏览器要求用户先和页面交互一次才能出声，所以第一次点击或按键之后才会有声音。静音设置保存在浏览器本地。

**减少动态效果**：如果系统开启了"减少动态效果"（`prefers-reduced-motion`），会关闭彩带、倒计时缩放等大幅动画。

## 4. 房间与玩家生命周期

| 场景 | 系统行为 | 怎么验证 |
|---|---|---|
| 刷新页面 | 用 sessionStorage 里的身份自动回到原座位，并收到全量状态；1.5 秒内重连成功的话，其他人看不到掉线提示 | 对局中按 F5 或 Cmd+R |
| 网络短暂中断 | 页面顶部显示"连接中断，正在重连…（第 N 次）"，按 0.5、1、2、4 秒的间隔自动重试；30 秒内恢复就回到原座位，超过 30 秒显示"重连失败"并提供「重新加入」 | 关闭网络几秒钟后再打开 |
| 掉线期间 | 座位保留 30 秒；角色原地冻结，冲刺冷却继续计时；其他人会在角色头上看到"掉线"标记，HUD 上显示"xx 掉线，重连中 Ns"，大厅里也有同样的倒计时 | 在同一个标签页里打开别的网址，然后按后退键回来 |
| 关闭标签页 | 对其他人来说和掉线一样。用 Ctrl/Cmd+Shift+T 恢复刚关闭的标签页，可以带着原身份回来；用新标签页打开链接则是一个新玩家 | — |
| 对局中只剩 1 名在线玩家 | 显示"在线玩家不足 2 人，Ns 后结束本局"；10 秒内有人回来就继续，否则提前结束，结算页写明"在线玩家不足 2 人超过 10 秒，本局提前结束，按当前格数结算" | 两人对局时关掉其中一方 |
| 对局中有人主动离开，剩下不足 2 人 | 立即结束，结算页写明"有玩家离开，场上不足 2 人" | 两人对局时一方点击离开 |
| 主动离开 | 立即被移出房间，其他人看到"xx 离开了房间" | 点击「离开房间」 |
| 房主离开或掉线超时 | 房主身份移交给下一位玩家，对方看到"你现在是房主"，其他人看到"xx 成为了房主" | 在大厅里让房主点击离开 |
| 对局中有人加入 | 加入页先提示"对局正在进行，你将先以观战身份进入，下一局自动加入"；进入后能看到实时画面，HUD 显示"观战中"；本局结束后，这个人在大厅里自动补位成为玩家 | 开局后用第三个标签页打开邀请链接 |
| 房间已有 4 名玩家 | 提示"房间已满（4/4），你可以先观战，有空位时下一局自动加入"；一旦有人离开，就自动补位，并提示"有空位了，你已加入下一局" | 用机器人凑满 4 人后再加入 |
| 观战席也满了（8 人） | 提示"房间已满：玩家和观战席位都满了"，并提供「创建新房间」 | — |
| 同一个身份在两个页面打开 | 后打开的页面接管连接；先打开的页面显示"你在另一个页面打开了这个房间"，提供「在这里继续」（把连接抢回来）和「以新玩家加入」 | 在 Chrome 中对房间标签页使用"复制标签页" |
| 结算后再来一局 | 第一个点击「再来一局」的人会把房间带回大厅，并自动处于准备状态；还停在结算页的人能看到"已在大厅：xx"，点击后同样进入大厅并自动准备；观战者看到的按钮是「回到大厅」 | 结算页点击「再来一局」 |
| 空房间 | 所有人离开 5 分钟后，房间被清理，之后再打开这个链接会显示"房间不存在或已失效" | — |
| 服务重启或重新部署 | 所有在线页面提示"服务器刚刚重启 · 房间已失效"，引导创建新房间 | 本地运行时按 Ctrl+C 停止服务 |
| 页面版本落后于服务端 | 提示刷新页面 | 部署新版本时可能遇到 |
| 操作过于频繁 | 建房、查房、加入过于频繁时提示"尝试次数过多，请稍后再试"；对局中发送过快的输入会被丢弃，但连接保持 | 由自动化测试覆盖 |

## 5. 实时同步

- **服务端权威**：服务端以 20 Hz 的固定 tick 推进模拟，客户端只发送输入 `{seq, tick, dir}` 或 `{seq, tick, dash}`。位置、分数和胜负全部由服务端计算，协议里根本没有让客户端上报这些数据的字段。
- **输入校验**：每条消息都经过 zod schema 校验，消息不超过 1 KB，每秒最多 20 条；seq 必须单调递增，重复或过期的输入会被丢弃并计数；单个 tick 最多处理 4 条输入；冲刺冷却和速度都由服务端规则决定。
- **下行同步**：加入或重连时下发全量快照，之后每个 tick 下发一条增量（变化的格子加上所有玩家的状态），每条都带 `(round, tick)` 编号。客户端会丢弃旧的或重复的消息；比预期超前 1–4 个 tick 的消息先缓存，等缺的那条到了再按顺序应用；补不齐时请求全量快照。每 20 个 tick 附带一次全图校验和，不一致时自动请求快照修复。
- **他人插值**：别人的移动按估算出的服务端时间做插值，画面匀速，不受网络抖动影响。
- **自己预测**：自己的操作在本地用同一份规则函数立即生效。输入会带上"希望在哪个 tick 生效"，服务端在那个 tick 应用（最多允许提前 10 个 tick），因此在正常延迟下，本地预测与服务端结果逐 tick 一致；不一致时用 90 ms 的平滑过渡纠正，不会瞬移。
- **计时与胜负**：通过 ping 估算客户端与服务端的时钟偏差，倒计时按服务端下发的结束时间 `endsAt` 显示，胜负只认服务端判定。

## 6. 弱网模拟与调试面板

在地址后加参数即可，例如 `https://turf-rush-gw9p.onrender.com/?lag=200&jitter=40&chaos=1`：

| 参数 | 作用 |
|---|---|
| `lag=200` | 在客户端额外加 200 ms 往返延迟（上行、下行各 100 ms），消息顺序保持不变 |
| `jitter=40` | 额外加 0–40 ms 的随机抖动，顺序同样保持不变 |
| `chaos=1` | 故意注入重复和乱序：约 5% 的下行 tick 重复投递，约 5% 与下一条交换顺序，约 5% 的上行输入重复发送 |
| `debug=1` | 只打开调试面板；带任何弱网参数时，面板也会自动打开 |

这些参数在站内跳转和刷新后都会保留，但复制出去的邀请链接不带这些参数，别人打开时是正常网络。

| 面板项 | 含义 | 正常表现 |
|---|---|---|
| 连接 | WebSocket 状态与时钟同步状态 | 已连接 · 时钟已同步 |
| ping (RTT) | 往返延迟 ± 抖动；超过 250 ms 显示为红色 | 本地接近 0；加 `lag=200` 时约 200–250 |
| 时钟偏差 | 估算的服务端时钟与本地时钟之差 | 稳定，不跳变 |
| 房间 | 房间码 · 阶段 · 第几局 | — |
| 权威 tick | 最新收到的服务端 tick / 本局总 tick 数 | 稳定增长 |
| 估计服务端 tick | 按时钟偏差推算出的服务端当前 tick | 略高于权威 tick |
| 他人插值 | 别人的画面落后于最新权威状态多少 tick | 0.5–1 左右 |
| 自己预测 | 自己的画面领先于权威状态多少 tick | 约等于单程延迟换算成的 tick 数 |
| 待确认输入 | 已发送、但服务端还没确认的输入数 | 0–2 |
| 预测纠正 | 本地预测与服务端结果不一致的次数 | 0 或很少 |
| 丢弃：过期/重复 tick | 被丢弃的重复或过期下行消息数 | 开启 chaos 后增长 |
| 乱序重排 | 先到后排、成功补齐的次数 | 开启 chaos 后增长 |
| 丢弃：过期房间状态 | 被丢弃的旧版本房间消息 | — |
| 丢弃：服务端拒收输入 | 服务端因重复、过期或超限而拒收的输入数（来自 pong 回包） | 开启 chaos 后会因为重复输入而增长 |
| 断档 / 校验不一致 | 补不齐的缺口次数 / 校验和不一致次数 | **应保持 0 / 0** |
| 全量快照 | 收到的全量快照次数 | 加入时 1 次，重连时加 1 |
| 已应用增量 | 已按顺序应用的增量数 | 持续增长 |
| chaos 注入 | 实际注入了多少重复和乱序 | 只在开启 chaos 时显示 |
| 帧率 | 渲染帧率 | 跟随显示器刷新率 |

**服务端可观测性**：`GET /healthz` 返回 `{ok, rooms, conns, tickLagMs}`，其中 `tickLagMs` 表示主循环落后的毫秒数。服务端日志是一行一条 JSON，记录建房、加入、掉线、重连、移除、房主移交、阶段切换、结算等事件。

## 7. 安全与隐私

- **防作弊**：协议中没有位置、分数和结果字段；输入经过 schema 校验并限流；seq 去重。
- **防劫持与注入**：WebSocket 只接受同源连接（校验 Origin）；设置了 CSP；昵称在服务端清洗，客户端只用 `textContent` 和 Canvas 输出文字，所以昵称里写 HTML 也只会按原样显示成文字。
- **身份**：重连 token 是 128 位随机值，按房间隔离，用恒定时间比较。
- **防滥用**：每个 IP 每分钟最多建房 10 次、查房或加入 30 次，最多同时保持 8 个连接；全服最多 200 个房间。
- **隐私**：没有账号、cookie、统计脚本，也不加载任何第三方资源。日志里不记录昵称，IP 只在连接被踢出或出错时写入日志。

详见 DECISIONS 第 7 节。

## 8. 开发者工具

| 命令 | 作用 |
|---|---|
| `npm start` | 构建前后端，并在 8080 端口同时提供页面和 WebSocket |
| `npm run dev` | 开发模式：服务端 8080（tsx watch），前端 5173（Vite，`/api` 和 `/ws` 代理到服务端） |
| `npm test` / `npm run typecheck` | 100 个单元测试与集成测试 / 对四个包做类型检查 |
| `npm run sim` | 回归测试：两名机器人通过 WebSocket 跑完整两局，覆盖作弊和重复输入、断线重连、中途观战、观战补位和房主移交，并断言各端结果一致；设置 `SIM_URL=https://…` 可对任意部署运行 |
| `npm run bots -- 房间码 3 [--url 地址]` | 往指定房间加入 1–3 个机器人，它们会自动准备、移动、冲刺，结算后再来一局 |
| `npm run verify` | 类型检查 + 测试 + 构建 + 回归 |
| `npm run package` | 生成免安装发行包 `release/turf-rush-app/`（服务端、前端、`tools/bots.js`、`tools/sim.js` 和启动脚本），只需要 Node.js 就能运行 |

| 环境变量 | 默认值 | 作用 |
|---|---|---|
| `PORT` | 8080 | 监听端口；端口被占用时，启动会给出提示 |
| `MATCH_SECONDS` | 60 | 每局时长（秒） |
| `TRUST_PROXY` | 未设置 | 设为 `1` 时从 `X-Forwarded-For` 读取客户端 IP，部署在反向代理后面时需要 |
| `ALLOWED_ORIGINS` | 空 | 额外允许的 WebSocket Origin，用逗号分隔 |
| `NODE_ENV` | 未设置 | 设为 `production` 时，静态文件元数据只在启动时读取一次 |

## 9. 不做的内容与已知限制

**不做**：账号、排行榜、匹配、聊天、多服务器扩展。

**已知限制**：
- 房间只保存在单个进程的内存里，重启后房间失效，页面会给出提示。
- Render 免费实例会休眠，冷启动约需 1 分钟。
- 触屏操作没有在真机上验证过。
